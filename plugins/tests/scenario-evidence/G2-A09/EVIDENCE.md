## Why the append-at-EOF change is in this pack

The first rerun attempt (same fix, same runner) reached the second turn but
then timed out: a `python3 -` heredoc writing the two 8 MiB shards in 1 MiB
`f.write` calls made the WASI VFS proxy publish each call as a whole-file
rewrite, so the WAL had to carry 1+2+…+8 MiB per shard. That attempt reached
the 256 MiB WAL budget, the shard write stopped at 4 MiB, and the turn was
cancelled by the scenario wall clock. The fix is a general write-path change,
not a G2-A09 special case: a `fd_write` whose offset equals the current file
length is dispatched as an append, and `NodeFsBackend` uses the VFS's real
`appendFile` face. The same byte stream lands in the file; the WAL now carries
only the new suffix (the second attempt's WAL stayed at 34 MiB and the whole
scenario passed in 80 s). `vfs-append.test.ts` pins both the append dispatch
and the fallback for facades without `appendFile`.

## Honest scope note

The pre-fix defect is not "stdin was never delivered on every path": the
happy-path heredoc in the baseline tree already delivered its bytes. What this
pack fixes and pins is the class that includes the wedged dispatch, the
interpreter that starts but never performs its first `fd_read(0)`, a truncated
delivery, an oversized stdin payload and a missing EOF — each now has a
structured failure (`E_EXEC_START_TIMEOUT`, `E_STDIN_READ_TIMEOUT`,
`E_STDIN_INCOMPLETE`, `E_STDIN_OVERSIZE`) instead of holding the Worker
command lane until the 120 s shell timeout. The real rerun above is the
end-to-end evidence for that class.
