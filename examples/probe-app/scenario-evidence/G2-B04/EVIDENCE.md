## Why `report.json` is still `FAIL`

The iOS Simulator runner cannot execute host processes. Its per-assertion
verdicts are therefore runner limitations, not python-toolbox behaviour:

- the three `workspace_command` assertions return
  `exit -1: host process execution is not available in the iOS scenario runner`
  (the runner has no `Process`; `ScenarioProcess.run` is macOS-only);
- `restart_recovered` compares a workspace snapshot taken while turn 1 was
  still writing with the state immediately after resume. The model's acked
  turn-1 writes (`bill_a.py`, `bill_b.py`, `bill_c.py`) landed inside that
  window, so the runner calls them "changed"; the transcript shows the files
  are the model's own acked edits, not lost or reverted state.

Both failures apply to every python scenario on this runner and are outside
this work package's write scope. The acceptance behaviour that this round had
to prove -- python3 seeing the same `/dsh` workspace as bash after the rebuild,
and the full unittest suite rerunning green -- is visible in the transcript
above.
