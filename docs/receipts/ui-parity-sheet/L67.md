# 三、结构性差异

## 3.1 抽屉宽度 320 vs 402 —— **L64 判错了，Android 的 320 是对的**

结论：**没有改**，改了会让 5 个状态变坏、只为对齐 1 个 iOS 预览壳的产物。

证据链：

1. iOS 生产抽屉就是 320：`NativeShell.swift:97` `private let drawerWidth: CGFloat = 320`，
   面板注释 `SessionsPage.swift:417/:593` 也按 320 算（「面板 320 减左右各 16」「线正好 288」）。
2. iOS 预览外壳 `DrawerPreview` 也是 320：`NativeShell.swift:889` `.frame(width: 320)`。
3. 但 `sessions-default` 走的是**另一条路**：`NativeShell.swift:828`
   `case .sessions: SessionsPage(onSelect: {})` —— 没有套 `DrawerPreview`，于是整页按 402 渲染。
   其余五个状态（many / empty / nothing / ungrouped / error）都套了 320 的外壳。
4. 像素实测（本次重采前后都一致）：

   | iOS 图 | CTA x 范围 | 宽度 | 容器 |
   |---|---|---|---|
   | `ios-sessions-default.png` | 16.0–385.7 | 370.0 pt | 402 |
   | `ios-sessions-nothing.png` | 16.0–303.7 | **288.0 pt** | **320** |
   | 分隔线（many/empty/nothing/ungrouped/error） | 16.0–303.7 | 288 | 320 |
   | 分隔线（default） | 57.0–344.7 | 288 | 402（288 居中） |

   Android 的 320 抽屉 + 16 边距 = 288 CTA，与 iOS 后五张**逐点相同**；`page-sessions-*` 五个状态
   在本轮跨平台比较里 0.00 % 变化，也说明它们本来就没差。

所以「CTA 369.7 vs 287.7、空态居中偏左 41.2」是 `sessions-default` 这一张的差，**根因在 iOS 的预览
路由**（`case .sessions` 该换成 `DrawerPreview(...)`），不在 Android。要改 iOS 的
`examples/**` 才能真对齐，本 lane 只读。

# 四、`chat` 67 vs 29：是门禁的**报数**错了，不是实现缺 38 个

`page_structure_check.py` 打印的 `contract 67` 是 `len(contract["actions"])`（**全部**动作），
而真正参与比对的是 `labelled`：去掉无文案的动作、去掉 `dynamicLabel`、去掉 `androidOnly`。

实测拆解（`--page chat`）：

| 项 | 个数 |
|---|---|
| 契约动作总数 | 67 |
| 无文案（图标按钮，`label: null`） | 27 |
| `dynamicLabel`（运行时拼的文案） | 4 |
| **参与比对的 `labelled`** | **36** |
| 36 个按 normalize 去重后的键 | 29（Android 也 29） |
| divergence | 0 |

所以 36 个可比动作 ↔ 29 个 Android label 是**同一个集合**（多个契约动作共享同一句文案，例如三个
「取消」），`divergences 0` 是真的。但那行摘要把 67 和 29 并排印出来，读起来像「少了 38 个」。
**建议**（本 lane 不能改 `spec/ui/v1/tools/**`）：摘要行改成打印 `len(labelled)`（或
`contract 67 labelled 36 (unique 29)`），并把「无文案 / 动态文案」各印一列。

真正没覆盖的是那 27 个图标按钮与 4 个动态文案动作：它们在两边都存在，只是这个门禁**按设计**不比
图标（README §1）。要覆盖得另加一列「按 `contentDescription` 比对」，不是这次能顺手做的。

# 五、找不到出处 / 不能补的

| 缺什么 | 为什么不补 |
|---|---|
| `#0088FF`（systemBlue） | iOS 源码里没有这个值：`启动本地引擎` 这类链接写的是 `.tint(.blue)` / `Color.accentColor`（`ModelProviderSettingsPage.swift:146`、`NativeAutomationPage.swift:63`），是系统动态色；#0088FF 是模拟器 P3 截图里 systemBlue 的**实测**值，不是可指的 sRGB 常量。token 格式只有 6 位 sRGB，没有 alpha，也没有「系统蓝」这一层，所以没造。要用它得先决定「页面里的系统蓝算不算 token」 |
| 白色 bar / 胶囊 | iOS 的白色导航条是 `Color(.systemBackground)`（`NativeChatTheme.swift:12`），token 里就是**未测量**的 `colors.background`；`完成` / `添加` / `新建` / `↻` 是 iOS 26 的**系统工具栏按钮**（`SettingsPage.swift:77` 只有一个裸 `Button`），白底、圆角、阴影全由系统画，源码里没有这三个值。造 `colors.bar` = #FFFFFF 等于把「未测量」抄成实测，`ui_check` 的 unmeasured 规则也会拒（除非标 unmeasured + null，那就等于没值） |
| 行高 52.33 | 见 3.3；只能指到 `minHeight: 48`（`NativeShell.swift:491`），52.33 是 List 行余量，没有一行写它 |
| `switchOn` 的对比度债 | 2.22:1 低于控件门槛 3.0，本该登记成 deferred 对；但 deferred 表和 8 对上限都归 README 的债表（本 lane 不可写），只能先记 `exempt(dynamic)`（`UIColor.systemGreen` 确为动态系统色），差额写在 note 里。**请 iOS owner 裁决** |
| `pdsd` 行间距 56.7 vs 56.0 | 按 parent 裁决「不确定就不要动」，未改 |
