## 6. 凍結裁定（D13 outline vs Swift/golden）

D13 是提案。依任務規則，Swift 實際行為 + 既有 golden 優先；以下是本 revision 的裁定，Kotlin 必須照此實作，不得照 outline 的文字。

1. **`/approval` 回應含 `pending` 與 additive 欄位。** Outline 只列 `{ok,allowed,approvalId?,message?}`；Swift 的 `BotApprovalOutcome.jsonValue` 固定輸出 `pending`，並在決定後加 `approvalDecision`/`scope`，durable pending 另加 `expiresAt`。裁定：以 Swift 為準；`pending` 是 required boolean，其餘 optional。理由：Worker 已有客戶端讀 `pending`，D13 的省略會讓 Kotlin 少一個 terminal/pending 判別。
2. **`alwaysScope:"none"` 對所有工具都可接受。** Outline 說 `none` 只用於 sandbox escalation；Swift 的 `approve` 允許 `alwaysScope == expectedScope || alwaysScope == "none"`，且 sandbox escalation 另要求 `none`。裁定：以 Swift 為準，`none` 是「這次 always 決策降級為 once」的通用表達；它不是放寬，而是收窄成一次性授權。B5 不得把 `none` 解讀成 session/until。
3. **`stale:*` refusal 是 `/approval` 的 200 JSON，不是 HTTP 4xx。** Outline 未說 status；Swift 全部回 200。裁定：200 + `{ok:false,allowed:false,pending:false,message:"stale:..."}`。
4. **`unknown_tool` 是 tool failure，不是 JSON-RPC error。** Outline 只說 unknown name 的 `-32602`；Swift 在沒有 native forwarder 認領時回 `BotMCPCallResult.failure("unknown_tool")`（`isError:true`），只有 encode 失敗才 `-32602`。裁定：以 Swift 為準；`-32602` 留給缺 name / arguments 非物件 / 極端 encode 失敗。B5 若把 unknown tool 當 JSON-RPC error，Worker 的 model-visible 文字會分叉。
5. **`/identity/register` 的精確字串多於 outline 的 enum。** Swift 另有 `invalid identity registration` 與 `argument digest mismatch`；outline 的 `identity registration refused` 是 catch-all。裁定：三個字串都 freeze；`identity registration refused` 不是獨立 enum value。
6. **Volatile 失敗不是 empty snapshot。** Outline 說 failed/slow/invalid 回 empty snapshot；Swift 的 `BotVolatileContextProducer` 回 `timeout`/`unavailable`/`cross_session_read_denied` tool failure，只有 provider 主動回空 blocks 才是空 snapshot。裁定：以 Swift 為準，並拒絕 stale/partial。
7. **`ListRoutines` 的 `inputSchema.additionalProperties:false` 不是執行期驗證。** Swift 不跑 JSON Schema engine，`ListRoutines` 忽略多餘成員；只有 JSON-RPC 層的非物件 `arguments` 會 `-32602`。裁定：`inputSchema` 是 advertised metadata；B5 必須逐工具實作 handler 規則。若 owner 要通用 schema 驗證，那是新 PC（會改變既有可接受呼叫）。
8. **`final` 只在五個 content card 驗證。** `ask_user`/`show_next_steps` 上的 `final` 被忽略（不是錯誤），且所有 content card 的 `final` 成功後從 payload 剝離。裁定：以 `BotCardPayloads.contentCardFinal` 為準。
9. **Synthetic “other” 的兩個 count 檢查。** Swift 先檢查 raw 2–4，移除「其他/其它/other」後再檢查 effective 2–4，因此有兩個不同錯誤字串。裁定：兩個都 freeze（`cards.md` §2/§8）。
10. **Native notification 不 forwarding。** `/mcp` 的 HTTP 層對沒有 `id` 的 message 直接回 202，不前送 native。裁定：freeze；native server 的 notification 只走 `/mcp/native`。
11. **Bearer scheme 大小寫敏感。** Swift 對 `Authorization` 的完整 byte string 比對 `"Bearer <token>"`，`bearer` 小寫是 401。裁定：freeze（與 `BotTokenRegistry.lookupBearer` 的寬鬆 scheme 是兩個不同入口，不得混用）。
12. **Listener token 不因 rebind/Worker restart 旋轉。** Outline 說 Worker restart 不 rotate、host restart rotate；Swift 的 token 在 `BotMCPHTTPServer` instance 上，rebind 不換、host restart 新 instance 才換。裁定：freeze，並把 egress token 的同規則交叉引用 §1.1。
13. **Cards 的 P1 fail-closed。** Outline 說 unknown tool/type 或 missing data fail closed；Swift 的 `build` 連 `show_table` 都以 `unknown or non-P0 card tool` 拒絕。裁定：P1 名稱不得註冊、不得由 builder 產生。
