# PhoneDSH App 设计合同（DESIGN）

- 版本：v0.2 · 人工门①评审稿（五 Tab 动态结构）
- 产品立场：独立 PhoneDSH，不是桌面客户端皮肤
- 适用顺序：先以此约束黑白结构，再指导高保真；人工门②后，`prototype/ + DESIGN.md` 共同成为实现合同
- 变更原则：门①只能低成本调整结构与状态；门②后视觉变更必须显式记录并同步原型和实现

## 1. 设计概念：Quiet Local Execution

PhoneDSH 的视觉应该像一个**安静、可信、随时能看清工作在何处的本地工作台**：

- 不用“AI 正在思考”的大动画证明智能，而用真实步骤、证据、产物和回执证明工作。
- 不让硬件渲染图压过任务；手机本身就是 Agent 宿主。
- 不让 Personal Agent 的个性化配置阻塞通用 DSH。
- 不让聊天淹没执行；任务、审批和文件有一等信息位置。
- 不把隐私藏进设置；数据路径、录音和授权在相关动作旁就能看懂。

一句话：**克制的外壳，清晰的执行。**

## 2. 借鉴与独立边界

### 从桌面客户端最新设计借鉴

- Dock、可变化的服务入口、线性图标与 Clean Glass 的克制原则。
- AI日记三环概览、时间线、原话回跳。
- Memory 的搜索、待确认、关于我、待办和隐私分区。
- 四列服务目录、Provider 与设备配对等代码能力（实现阶段另行评估）。

### PhoneDSH 独立重构

- 首次启动默认 DSH，而不是账号、硬件或 Personal Agent 的欢迎向导。
- Personal Agent 配置采用 needsApiKey → needsNaming → ready；完成后 Dock 才增加 AI日记。
- DSH 是完整通用 Harness 工作台，不是 Personal Agent 的附属任务列表。
- Memory 收进个人；发现统一硬件、连接器和服务应用目录。
- 设备入口按场景分布：Chat 管当前对话，AI日记管录音来源，发现管统一目录；底层共用同一设备与授权状态。
- 不强制登录、不使用云端 DSH 叙事、不复制桌面/实时客户端的空间声场或硬件灯光语言。

## 3. 信息层级

每屏按以下顺序分配注意力：

1. **正在发生什么**：引擎、任务、录音、设备状态。
2. **需要用户做什么**：配置、确认、补充输入、恢复、重试。
3. **已经产生什么**：回答、文件、纪要、记忆、真实回执。
4. **可以进一步了解什么**：过程、来源、修订、诊断。

首页不允许用大型欢迎插画或装饰卡挤掉第 1、2 层。首次启动直接呈现 DSH 工作区，而不是营销欢迎页。

## 4. 黑白低保真约束（当前门①）

- 仅使用黑、白和灰阶；不使用品牌色、渐变、玻璃 blur、彩色插画或装饰阴影。
- 允许用 1px 边框、灰底、虚实线、字重、间距和形状区分状态。
- 原型重点是页面树、内容顺序、术语、状态、密度、返回路径与触控可达性。
- 不用 emoji 代替图标；使用统一的线性 SVG 或文字符号。
- 所有 Mock 数据与动作可见标识，但不允许用巨大的“演示”横幅遮挡每屏内容。

| `text.secondary` | `#55555C` | `#B8B8C0` | 次级信息 |

### 5.3 字体

- iOS：SF Pro；中文系统字体 PingFang SC。
- HTML 原型：system-ui / -apple-system / PingFang SC / sans-serif。
- 数据、token、用量和版本号使用等宽数字，不为阅读正文换等宽字体。

| 样式 | 字号/行高 | 用途 |
| --- | --- | --- |
| Display | 34 / 40 · Bold | 页面大标题，最多一个 |
| Title | 22 / 28 · Semibold | 详情标题、关键任务 |
| Headline | 17 / 24 · Semibold | 卡片标题 |
| Body | 16 / 25 · Regular | 正文与对话 |
| Secondary | 14 / 20 · Regular | 次级说明 |
| Caption | 12 / 16 · Regular | 状态、来源、时间 |
| Micro | 11 / 14 · Medium | 徽标，不用于长文 |

### 5.4 间距、圆角、触控与动态 Dock

- 间距刻度：4 / 8 / 12 / 16 / 24 / 32 / 48。
- 页面水平边距：16；卡片内边距：16；相关元素间隔：8；区块间隔：24。
- 圆角：小控件 10、输入与芯片 999、卡片 16–20、弹层 24。
- 触控目标最小 44×44；图标视觉尺寸可以是 20–24，但点击区域不能缩小。
- Dock：左右边距 16；独立 Chat 圆形入口 64；其余入口组成一条工具栏，高 64。
- 未配置 Personal Agent 时工具栏为 DSH / 发现 / 个人三格；配置完成后插入 AI日记成为四格。网格列数随实际入口变化，不保留空槽。
- 正文底部预留至少 104 + safe area。

## 6. 核心组件

### 6.1 EngineHeader

内容：本地引擎状态、当前输入设备、可选待确认数。它是状态组件，不是品牌大图。

- 正常最多两行。
- 失败时主动作是“查看恢复”，不是 technical error code。
- 离线时保留本地历史，不把全屏变成断网页。

### 6.2 AgentSetupCard

用于 Personal Agent 未配置与渐进配置：

- 未配置明确显示 needsApiKey、配置入口和“先去 DSH”。
- key 配置完成后必须经过 Agent 名与主人称呼，不直接伪造个性化历史。
- ready 后全局显示同一个 Agent 名，AI日记同时出现。
- 不强制账号登录，不在此页申请全部硬件权限。

### 6.3 DSHNativeHome

DSH 首页沿用当前 PhoneDSH 原生会话主页：会话标题 → 运行状态 → 消息流 → Composer；会话抽屉承载其他会话、定时任务、工作区和设置。

- 首屏直接呈现“新会话 / 引擎还没启动”的空态，不另做任务列表、营销卡或预设说明消息；启动后呈现真实消息流。
- 执行中可打开 TaskRun 详情或请求取消。
- 待确认以“去确认”为主操作。
- 完成展示产物，不继续显示“正在执行”。
- 未知显示“结果待对账”，不提供直接重试。
- Personal Agent Chat 是个性化轻量对话，不能与 DSH 原生会话页混成同一组件。

### 6.4 ApprovalCard

必须显示：动作、目标、正文/参数摘要、数据范围、Provider、费用（未知则明示）、后果、允许一次、拒绝。

- 不以“OK”作为授权按钮。
- “以后同类允许”默认不选，首版可从确认卡省略。
- 过期、撤权或参数变化后旧卡失效。

### 6.5 EvidenceLink

统一表达“查看依据”：原话、原文件、执行记录、Provider 回执。

- 摘要是派生物，证据链接紧跟对应内容。
- 来源不可用时显示受限原因，不能打开伪造原文。
- 证据不支持复制内部 token、签名 URL 或 MAC。

### 6.6 RecapRings

沿用当前桌面客户端日记的信息顺序：日期导航与来源入口 → 当日大标题 → 三环（记录 / 对话 / 要点）→ 记录状态 → 今日要点 → 今日 AI 日记 → 当日总结。

- 黑白稿只用灰阶环；高保真才使用语义色。
- 记录环显示合并覆盖区间后的时长与小时单位，不是条目数；另两环分别显示对话数和要点数。
- 数据不完整时显示缺口，不画满圈；日记与录音状态分开，不把“有日记”误作“正在录音”。
- 今日要点进入来龙去脉；时间线保留对话原话、纪要和 Agent 工作的入口。

### 6.7 MemoryCard

正文优先，随后是状态、来源和版本；候选与已确认在文字上明确。

- 待确认卡的主操作是“查看并决定”，不是一键全部接受。
- 遗忘和重置进入二次确认，结果写实际范围。
- 记忆引用可以回到原话，不重新生成一个来源。

### 6.8 DeviceStatusRow

设备名、连接状态、实际能力、当前授权、状态 revision。

- Ready 之前不展示可执行控制。
- 离线时控制禁用但状态可读。
- 不展示 MAC、内部 device_id、loopback 地址或密钥。
- Chat 与 AI日记的快捷入口最终都打开同一设备详情，不生成相互矛盾的连接状态。

## 7. 页面与状态表现

- **加载**：骨架保持布局稳定，不用全屏 spinner 取代所有内容。
- **空**：一句原因 + 一个主动作，避免多张空卡片。
- **未配置**：明确告诉用户缺什么、如何配置，以及能否先用 DSH。
- **离线**：顶部或原位提示，历史保留；不全局弹窗打断。
- **失败**：保留最后可用内容，错误行提供重试/对账。
- **等待**：说明在等谁——用户、设备、Provider、系统还是引擎。
- **后台**：显示最后检查点与恢复入口，不假装持续进度。
- **权限**：说明具体能力和系统路径，不一次索取全部权限。

详细矩阵以 [states.md](states.md) 为准。

## 8. 动效与反馈

- 页面切换 160–240ms；状态更新 120–200ms；不循环播放“思考”光效。
- 新转写整句淡入；任务进度按真实事件更新，不按定时器伪造。
- AI日记出现只更新 Dock，不强行把用户从当前 Tab 切走。
- Toast 出现在 Dock 上方，不遮主操作；可撤销动作显示一次撤销。
- 遵循“减少动态效果”：关闭脉冲、进度动画和非必要过渡。

## 9. 可访问性与国际化

- 所有图标按钮有可访问名称；选中、禁用和等待不只靠颜色。
- 文本对比按 WCAG AA；辅助文字也不能用低透明度导致不可读。
- 支持动态字体时，卡片高度随内容增长，不用固定高度截断正文。
- 首版中文文案用于结构评审，所有字符串在实现阶段进入翻译表，预留英文约 30–40% 膨胀。
- 界面语言、生成内容语言和转写语言分开，不从 Provider 推断。

## 10. 真实性与 Mock 规则

- 原型统一使用虚构数据，不能输入或截图真实 key、用户原文或个人信息。
- “验证 API key”“推进任务”“配对成功”“发送飞书”只改变 Mock 状态，并显示 `Mock 回执`。
- 可以演示 `outcome_unknown`、失败和权限拒绝，不允许为了好看只保留成功路径。
- 高保真截图用于视觉评审，不得作为后台、BLE、Provider 或生产链路验收证据。

## 11. 实现合同与验收

人工门②后：

- SwiftUI 的信息架构、页面状态、组件语义和文案以已批原型与本文件为合同。
- 实现可以自由选择架构和代码组织，但不能自由改变 Dock 的出现条件、状态含义、返回路径或授权语义。
- 使用相同 hash 路由对应的页面、相同 mock、相同 390×844 视口进行截图 diff。
- 视觉 diff 只证明实现接近原型，不替代真实设备、后台、BLE、模型、数据恢复和隐私验收。
