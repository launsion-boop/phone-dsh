# BLE / LAN 设备与 Skill 接入：联调工作单

状态：draft，尚未冻结或实现。Protocol impact: P07。基线：`8ab1dde58abd21b5d057e995afd3cd1d93ba8e6f`。

## 目标与范围

手机发现并经用户确认连接设备，读取设备声明的工具，让 phoneDSH 在授权后调用，并将设备结果交回会话。第一轮以文本和有限大小的控制命令为范围；音频与其他流媒体另行设计。设备能力、会话信封和命令回执继续以 `spec/host/v1` 为手机侧权威。设备的工具描述不是可执行的系统指令。

## 已有资产

- `codex/pdsh-ble-link` 的 `e76cecd4`：标准 GATT，以及基于 上游 Link 的 PDSH Link Tools Profile；支持 `tools/list`、调用和结果查询，含 iOS、ESP32 参考实现与测试。该分支文档记录了 iPhone 14 Pro / ESP32-S3 真机验证；本工作单未重新运行。
- 同一固件族的 `tonolink-ag00a/main/link_tools.c` 已有 `tools/list`；实际固件版本和手机侧支持情况需要逐设备协商，不能根据设备名推断。
- 旧 TonoLink 分支有 BLE 控制、USB NCM OTA 和手机上的局域网调试 relay；relay 曾设计为局域网无凭证访问，不能直接作为通用设备接入入口。
- 当前仓库 P07 提供设备能力、信封、回执的 schema 和 connector 接口；真实 BLE/LAN 开放协议、通用 Skill 清单及两端映射尚未冻结。

## 建议的边界

1. 发现只提供候选地址与协议线索，不授予信任。BLE 使用既有 service UUID 扫描；LAN 优先 DNS-SD/mDNS，提供手动地址兜底。发现信息不含凭证或完整 Skill。
2. 连接后先完成适配器各自的认证和版本协商，再读取设备身份、能力和工具清单；用户逐设备授权。设备名、广播、IP 和 CoreBluetooth 标识均不能单独证明身份。
3. Skill 在手机侧表现为工具描述与输入 schema；模型只能看到设备真实声明且用户授权的工具。调用继续经现有门禁与审计。工具描述和设备结果是非可信数据。
4. 适配器负责把各自 wire 映射到 P07 的 `pdsh-device-caps/1`、DeviceEnvelope 和 DeviceReceipt。PDSH Link 的 `completed`、`failed`、`outcome_unknown` 必须在映射前保留原始语义：未知结果不能伪造成 `applied` 或设备 `failed` 回执。
5. 有副作用的调用使用稳定操作 ID、内容冲突检测和有限期限；提交后断线或超时保留未知结果，只有具备查询或安全去重依据时才恢复，不盲目重新执行。发现、读取与控制权限分开。
6. LAN 传输必须同时确定加密、配对、设备身份验证、吊销和重放防护；只在私网监听或发现设备不足以认证。设备不接收模型供应商密钥；推理凭据和用量仍由现有 host/服务处理。

## 冻结前必须解决的差异

- BLE Link 当前使用 `tools/list`、`request_id`、`idem_key` 及 `completed/failed/outcome_unknown`；P07 的 capability/receipt 形状不同。要定义完整映射与未知结果的表示，并提供共享正反例；不能新增同义信封绕过既有 P07。
- LAN 尚无经确认的设备侧通用实现。需要选择并固定现有设备可实现的认证、发现和调用协议，明确证书/密钥首次绑定与轮换；不能把 TonoLink 调试 relay 的访问方式当作配对协议。
- Skill 描述的字段、JSON Schema 方言、数量/大小限制、名称冲突、未知字段、版本与授权更新机制尚待确定。广播与已认证连接上的清单必须区分。
- P07 当前 receipt 仅有 `applied/failed`，传输不确定状态如何表达须先由 contract owner 决定并更新权威文件，不得将未知结果视为失败或成功。
- `device-adapter-contract-draft.md` 要求重连后续传，而 `device-connector-2026-10-31.md` 把重传责任交给手机 Outbox；两者尚有冲突。应根据设备实际可持久化与去重能力决议，不能声称所有设备均具备续传。

## 接线顺序和验收

1. 以 `docs/protocol-change-template.md` 冻结 P07 delta：权威 spec/schema、共享有效与无效 fixtures、兼容矩阵、各端路径与命令；先解决上述冲突。
2. 从 `e76cecd4` 按路径迁移 BLE 实现及所需固件，适配当前 P07 和现有 native MCP；核对当前依赖与资源，不整体合并旧分支。
3. LAN 完成设备侧与手机侧配套实现，先以一个可复现的参考设备验证发现、认证、清单、调用和回执。
4. 同一批 fixtures 驱动真实两端解析器，覆盖非法输入、未授权、重复/冲突、超时、断线及重启后未知结果；最后在实际 iPhone 与 ESP32 上验证。

当前状态：协议设计准备中；BLE/LAN 接线、共同 fixtures、各端一致性和本轮真机验证均未完成。不得把旧分支历史证据当成本次验证。

## 协议冲突的协调决定（待写入冻结版）

- **结果未知**：`DeviceReceipt` 只表达设备确证的 `applied` 或 `failed`。超时、断线和设备无法证明历史结果均停留在手机端的未决操作状态，保留原命令 ID 和设备身份；不合成 receipt、不把本地超时当作设备失败。重连只查询原 ID；仅当设备协议明确承诺持久去重且在有效范围内时才允许同 ID、同内容重投。
- **续传与重连**：自动重连是适配器可以提供的能力，并非所有设备 60 秒内必达的承诺。手机可持久化待查询操作，但设备没有持久去重或结果查询时不能由手机单方面保证至少一次和不重复执行。事件无设备持久日志及游标时明确标记尽力交付，断线期间可能丢失。
- **现有版本**：保持 P07 现有 receipt 和 capability schema。旧 BLE Link 使用其既有字段、opcode、上限与协商；新适配器在边界映射，不修改旧固件语义。旧设备不支持工具扩展时不发送扩展请求。
- **共同事实源**：设备声明的工具清单经过适配器解码和用户授权后成为可调用工具；`pdsh-device-caps/1` 继续表示 P07 已登记的能力。Skill 工具目录的具体 schema 及两端的有效/无效共享样例必须在实现前冻结。
